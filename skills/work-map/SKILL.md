---
name: work-map
description: Inspect Work Map and maintain its project areas, tasks and session connections through shared UI and CLI operations. Use for Work Map questions or authorized project maintenance. Session creation and settlement still require explicit user action.
---

Work Map lives at `/plugins/work-map/map` in BB's sidebar.

Overview is spatial. Filters, search and Show all use a ranked single-column list with inline expansion. The order stays fixed during inspection. A result that no longer matches after reading stays visible until collapse, with an explanatory note. The side pane remains optional.

Waiting for you contains action requests, failures, Review tasks and due follow-ups. Successful unread responses have a separate quiet blue New result cue and New results filter; unread does not imply a review request. A task may appear in both filters. Reading its displayed successful result leaves its Review state intact. Input requests are strongest, review is a restrained amber outline, and project containers stay neutral with specific attention counts. Focus rings and working bars remain independent. Do not infer task completion or required human review merely from an agent finishing.

Zoom uses buttons, a slider, pinch or Ctrl/Command + wheel over the map. Map-focused Ctrl/Command with +, - or 0 also works. It ranges from 60% to 160%, snaps at 100%, and offers a small reset button away from actual size. Zoom out shows more areas and project tasks with less detail; zoom in narrows the Overview and reveals longer excerpts around the inspected item or pointer. Expanded areas keep their membership and order. Native chat and settlement controls stay at normal size. Zoom does not acknowledge results or change work state; rotation pauses while zoomed.

Run `bb work-map status --json` for task, project and session-link coverage. Read `README.md` in the plugin root for state and ranking rules.

BB owns session activity, pins and read state. Tasks owns task status, priority, date and thread attachments. Work Map's own storage contains task/project focus choices, seen task-update timestamps, session-creation receipts and settlement recovery receipts. Creation receipts contain request, thread and task identifiers, no prompt bodies. Settlement receipts retain before/after task fields and archived session identifiers for Undo. Its focus controls also write native BB pins: removing a task's inherited focus unpins every attached pinned session. The preview explains this effect. Work Map does not maintain a second task list. It has no settings, scheduled jobs or independent external services.

Only explicit settlement buttons change existing task status and handoff fields. Pause here preserves status and saves the next step; Ready for review selects Me (native Review) or Someone else (open todo with a waiting label, reviewer and follow-up date); Task done sets done. Handoffs update STATE, NEXT ACTION and lifecycle fields while preserving the description body/history, due date, priority and unrelated labels. Tasks records the click as a user action. No message is sent to a reviewer. External review becomes attention on its follow-up date.

For authorized project maintenance, agents can use `bb work-map project list|create|edit|hide|restore`, `bb work-map task create`, and `bb work-map attach TASK-KEY --thread THREAD-ID`. Run `bb work-map project --help` for exact flags; `--json` gives structured results. These use the same validation as the compact + and ⋯ controls. Inspect existing projects and deduplicate tasks before creating work. Supply an existing folder and BB workspace when appropriate; the CLI creates projects unfiled and unlinked when those flags are omitted. Retain the returned request id for retries (`--request-id`); if the outcome is uncertain, inspect existing work before making a new request. Do not change live work merely to test the UI.

Areas are Tasks projects. Manage areas includes empty and hidden projects. Hiding affects Overview only; search, attention filters and Show all still include their work. Hide/restore never archive sessions, close tasks or stop agents. There is no project archive, project deletion or task move in Work Map. Project names, color dots, folders and linked workspaces are editable; task prefixes stay stable after creation. Connecting a session requires an open task in the selected project. New tasks start in backlog with the supplied description and no invented lifecycle evidence. Work Map additionally stores visibility choices and creation receipts containing request hashes and resulting project/task metadata; these receipts do not store task descriptions.

The selected attached session is archived unless its checkbox is cleared. Standalone and newly created sessions have Archive session. Archiving stops running work. Sessions with children or source forks stay open because BB archives recursively; the task action can still succeed. Attachments are never removed. Settled today retains successful actions with Undo; Undo checks newer task content before restoring fields and unarchives the recorded sessions. It does not restart agents, recreate environments or erase Tasks audit history. These actions are not permission for an agent to settle live work during diagnosis or UI verification.

New session opens the native BB composer inline, globally or in an expanded task/project. It retains BB's project, model, environment, attachment and permission controls. The task/project context is an editable prompt seed; linked BB projects seed the project picker. Only submission starts a session. New task sessions attach through Tasks; project sessions do not invent task ownership. The created native chat stays inline with a full-session link. Failed attachment has a separate retry that never dispatches another session. Closing a draft preserves it through BB's native draft store.

The page refreshes task data and attachments every minute while visible. It picks up task attachments made after a session started. Agent comments with a recorded thread provide separate contribution links, not task ownership or activity. Unchanged closed-task comment history is cached for five minutes; Refresh map bypasses the caches. BB does not record the originating session of every task create/update, so those missing links cannot be inferred.

Clicks expand and collapse items in their existing part of the map. Neighbors compact to make room; their status colors and hidden-task counts remain visible. Short transitions show layout changes, respecting reduced motion. Projects retain their context when a child task expands. The side pane is an explicit option. Session activity follows BB's sidebar live. Expanding an individual successful result marks that displayed response seen. Browsing a project never marks all its sessions seen. Errors need explicit acknowledgment. Full task or session links use BB's existing navigation.
