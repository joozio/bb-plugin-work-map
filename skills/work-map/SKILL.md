---
name: work-map
description: Inspect Work Map and maintain its project areas, tasks and session connections through shared UI and CLI operations. Use for Work Map questions or authorized project maintenance. Session creation and settlement still require explicit user action.
---

Work Map lives at `/plugins/work-map/map` in BB's sidebar.

Collapsed Overview fits the available width and height, showing fewer whole cards on smaller screens. Show all reaches the remaining work. A short, narrow window uses a filter picker instead of clipped chips. If no root card fits, the caption directs the user to Show all. Project cards use Explore tasks when no children fit, and an overflow count when some fit. Expanded details, chat and drafts can scroll. Filters, search and Show all use a ranked single-column list with inline expansion. The order stays fixed during inspection. A result that no longer matches after reading stays visible until collapse, with an explanatory note. The side pane remains optional.

The center has a larger budget for useful information. Central sessions show longer latest-response excerpts and related task keys; tasks show next step, distinct status, priority and session count. Central projects show a longer lead summary and the highest-ranked children that fit. Narrow views put the center first. These are existing task/session data, not inferred metrics or newly fetched external data. Quiet cards omit repeated Inactive badges; external waiting reasons remain visible. All shown standalone sessions load excerpts in batches of up to 16, without a placeholder when none is available.

Waiting for you contains action requests, failures, Review tasks and due follow-ups. Successful unread responses have a filled blue Ready to read badge with a message icon, a blue card edge/tint and a matching Ready to read filter; unread does not imply a review request. They rank ahead of routine review queues. Up to two result areas are reserved alongside running agents; older results share remaining queue space so unread backlogs do not hide all other activity. Newest results sit centrally, with additional results in the side columns, including when zooming out. Pins and explicit input/failure attention retain priority. Expanded work keeps its position until collapse while the badge updates immediately. A task may appear in both filters. Reading its displayed successful result leaves its Review state intact. Review uses a restrained amber outline, and project containers keep neutral fills and specific attention counts, with a restrained blue border for unread results. Focus rings and working bars remain independent. Do not infer task completion or required human review merely from an agent finishing.

Zoom uses buttons, a slider, pinch or Ctrl/Command + wheel over the map. Map-focused Ctrl/Command with +, - or 0 also works. It ranges from 60% to 160%, snaps at 100%, and offers a small reset button away from actual size. Zoom changes card layout and content without scaling the interface. Zoom out fits more root projects and standalone sessions along both sides, up to 32 when space allows. Peripheral cards become compact titles and state labels; central cards retain useful context. Project task counts fit their card budget. Zoom in gives fewer cards more room for detail. Reset restores the default density for the current window. The caption reports the visible root count. Expanded areas keep their membership and order. Native chat and settlement controls stay at normal size. Zoom does not acknowledge results or change work state; rotation pauses while zoomed.

Run `bb work-map status --json` for task, project and session-link coverage. Read `README.md` in the plugin root for state and ranking rules.

Focus stays larger at every zoom. Recent activity adds proximity without implying a running agent: work active within 24 hours avoids the outer bands, and up to two recently active quiet areas keep a slot after focused work, explicit input/failures, unread results, running agents and one review/follow-up area. Other recent items share remaining space. Review and due follow-up work stay in the inner area too. Task lists combine priority, dates and recency without reserved recent slots. Fresh lower-priority work can precede an old high-priority task; an overdue urgent task keeps precedence. Activity weight halves each day; older quiet work moves outward as newer work arrives. Session activity comes from BB's latest attention timestamp with creation as fallback. Tasks include their own updates and explicitly attached session activity; projects include activity from all their tasks, including completed ones. Preview reads and comment-only connections do not renew activity. The muted age label explains recency. Time advances on the visible minute refresh even if source loading fails; open details keep their placement. None of this changes BB activity, task state or pins.

BB owns session activity, pins and read state. Tasks owns task status, priority, date and thread attachments. Work Map's own storage contains task/project focus choices, seen task-update timestamps, session-creation receipts and settlement recovery receipts. Creation receipts contain request, thread and task identifiers, no prompt bodies. Settlement receipts retain before/after task fields and archived session identifiers for Undo. Its focus controls also write native BB pins: removing a task's inherited focus unpins every attached pinned session. The preview explains this effect. Work Map does not maintain a second task list. It has no settings, scheduled jobs or independent external services.

Expanded task details show one status/next-step summary, compact metadata and session choices before task actions. Utilities use quiet buttons; New session stays with the connected sessions. Pause here and Ready for review open a small form; Save and pause or Save review performs the write. Cancel or Escape from a text field discards the handoff draft before collapsing the task; Escape in the reviewer dropdown leaves the form open. Task done stays one click and ignores unsaved handoff edits.

Only explicit settlement buttons change existing task status and handoff fields. Pause here preserves status and saves the next step; Ready for review selects Me (native Review) or Someone else (open todo with a waiting label, reviewer and follow-up date); Task done sets done. Handoffs update STATE, NEXT ACTION and lifecycle fields while preserving the description body/history, due date, priority and unrelated labels. Tasks records the click as a user action. No message is sent to a reviewer. External review becomes attention on its follow-up date.

For authorized project maintenance, agents can use `bb work-map project list|create|edit|hide|restore`, `bb work-map task create`, and `bb work-map attach TASK-KEY --thread THREAD-ID`. Run `bb work-map project --help` for exact flags; `--json` gives structured results. These use the same validation as the compact + and ⋯ controls. Inspect existing projects and deduplicate tasks before creating work. Supply an existing folder and BB workspace when appropriate; the CLI creates projects unfiled and unlinked when those flags are omitted. Retain the returned request id for retries (`--request-id`); if the outcome is uncertain, inspect existing work before making a new request. Do not change live work merely to test the UI.

Areas are Tasks projects. Manage areas includes empty and hidden projects. Hiding affects Overview only; search, attention filters and Show all still include their work. Hide/restore never archive sessions, close tasks or stop agents. There is no project archive, project deletion or task move in Work Map. Project names, color dots, folders and linked workspaces are editable; task prefixes stay stable after creation. Connecting a session requires an open task in the selected project. New tasks start in backlog with the supplied description and no invented lifecycle evidence. Work Map additionally stores visibility choices and creation receipts containing request hashes and resulting project/task metadata; these receipts do not store task descriptions.

The selected attached session is archived unless its checkbox is cleared. Standalone and newly created sessions have Archive session. Archiving stops running work. Sessions with children or source forks stay open because BB archives recursively; the task action can still succeed. Attachments are never removed. Settled today retains successful actions with Undo. The compact strip closes with × or Escape and reopens through a small history button; dismissal survives data refreshes and never changes work or deletes receipts. Browser-tab storage also remembers dismissed receipt identifiers across view reloads when available. New settlements or errors reopen it. Details/History reveals full receipts; Undo checks newer task content before restoring fields and unarchives the recorded sessions. It does not restart agents, recreate environments or erase Tasks audit history. These actions are not permission for an agent to settle live work during diagnosis or UI verification.

New session opens the native BB composer inline, globally or in an expanded task/project. It retains BB's project, model, environment, attachment and permission controls. The task/project context is an editable prompt seed; linked BB projects seed the project picker. Only submission starts a session. New task sessions attach through Tasks; project sessions do not invent task ownership. The created native chat stays inline with a full-session link. Failed attachment has a separate retry that never dispatches another session. Closing a draft preserves it through BB's native draft store.

Chat here opens an existing active session's native BB chat inside its expanded details or optional pane. Tasks initially choose an attached session by input request, failure, unread result, running state, then recent activity. The choice stays fixed after reading or activity changes; a removed connection falls back to a remaining attachment. Select a different attached or contributing session explicitly when needed. BB owns streaming, drafts, sends, queue/steer/stop, interactions and read tracking; the existing session's permissions are inherited. Work Map does not acknowledge hidden excerpts while live chat is visible. Back to summary, Escape or re-clicking the expanded item closes the chat layer before the task/project layer. Archived or unavailable sessions keep the full-session link. Opening chat is not permission for an agent to send messages during verification.

The page refreshes task data and attachments every minute while visible. It picks up task attachments made after a session started. Agent comments with a recorded thread provide separate contribution links, not task ownership or activity. Unchanged closed-task comment history is cached for five minutes; Refresh map bypasses the caches. BB does not record the originating session of every task create/update, so those missing links cannot be inferred.

Clicks expand and collapse items in their existing part of the map. Neighbors compact to make room; their status colors and hidden-task counts remain visible. Short transitions show layout changes, respecting reduced motion. Projects retain their context when a child task expands. The side pane is an explicit option. Session activity follows BB's sidebar live. Expanding an individual successful result marks that displayed response seen. Browsing a project never marks all its sessions seen. Errors need explicit acknowledgment in the summary view. Full task or session links use BB's existing navigation.
